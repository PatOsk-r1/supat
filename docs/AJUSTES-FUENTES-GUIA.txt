GUÍA DE AJUSTES DE SUPAT: CÓMO SE COMPLETA CADA CAMPO DE "FUENTES DE CONTENIDO"
Versión 2 (2026-11-05). Escrita a partir del código real de Supat: describe lo que el programa HACE con cada campo.

NOTA: desde la versión con "modo simple", en Ajustes alcanza con pegar la dirección de películas
(y opcionalmente la de series y la de episodios de una serie) más la API Key, y tocar "Detectar".
Supat completa solo todos los campos de esta guía. Esta guía sirve para la "Configuración avanzada":
corregir algo puntual o configurar una fuente que no se detecte sola.

######################################################################
PARTE 0. INSTRUCCIONES PARA EL ASISTENTE (leer primero)
######################################################################
Vas a recibir esta guía y la documentación técnica de una API de contenido (películas o series).
Tu tarea es decir qué valor va en cada campo del formulario de Supat.

REGLAS:
1. Usá SOLO datos que estén en la documentación o en los ejemplos de respuesta. Si algo no está, escribí "NO INFORMADO", no lo supongas.
2. Usá los NOMBRES DE CAMPO EXACTOS de esta guía. En las listas desplegables, usá el texto EXACTO de la opción.
3. Las rutas JSON se escriben con la sintaxis de la PARTE 1. NO uses JSONPath ($.data), ni barras (data/results), ni corchetes con comillas (["data"]).
4. Los campos SECRETOS (API Key, Token, Usuario, Contraseña, Credencial de reproducción, Encabezados personalizados, Parámetros de autenticación) NUNCA se completan con valores: escribí "CARGA EL DUEÑO".
5. Antes de completar, revisá la PARTE 9 (cosas que Supat NO puede hacer). Si la API cae ahí, decilo al principio.
6. Respondé con la plantilla de la PARTE 10, sin cambiar el orden.
7. Si un dato depende de una prueba (por ejemplo si el video permite CORS), marcalo "VERIFICAR CON LA PRUEBA".

######################################################################
PARTE 1. CÓMO FUNCIONAN LAS RUTAS JSON (lo más importante)
######################################################################
Una "ruta" dice dónde está un dato dentro de la respuesta JSON.

SINTAXIS:
  campo                  → { "campo": ... }
  a.b                    → { "a": { "b": ... } }
  a[0].b                 → el "b" del PRIMER elemento de la lista "a"
  a[].b                  → el "b" de TODOS los elementos de la lista "a" (devuelve una lista)
  a|b                    → usa "a"; si está vacío o no existe, usa "b"
  Solo se usan punto, [n], [] y |. No hay filtros, funciones ni comodines.
  No se pueden leer claves que tengan un punto en el nombre (por ejemplo "image.url" como nombre literal).

DESDE DÓNDE SE MIDE CADA RUTA (error muy común):
  - "Ruta del array de resultados": desde la RAÍZ de la respuesta, hasta la LISTA de títulos.
      Respuesta { "data": { "items": [ ... ] } } → data.items
      Si la respuesta ya ES la lista [ ... ] → dejar VACÍO.
  - Campos de MAPEO (ID, Título, Póster, Episodios: ID, etc.): desde CADA ELEMENTO de esa lista, NO desde la raíz.
      Elemento { "id": 5, "info": { "name": "X" } } → Título = info.name   (NO data.items[].info.name)
  - Rutas de PAGINACIÓN (total de páginas, cursor, enlace siguiente, última página): desde la RAÍZ de la respuesta.
  - Rutas del ENDPOINT DE REPRODUCCIÓN (URL, formato, vencimiento, subtítulos): desde la RAÍZ de la respuesta de ese endpoint.

######################################################################
PARTE 2. VARIABLES {...}
######################################################################
Se escriben entre llaves dentro de rutas de endpoints, parámetros y plantillas.

En ENDPOINTS DE CATÁLOGO (películas, series, anime):
  {page} {offset} {cursor} {limit} {since}. Normalmente NO hace falta escribirlas: Supat las agrega solo con los campos de paginación (PARTE 5).

En ENDPOINT DE TEMPORADAS y ENDPOINT DE EPISODIOS:
  {id}        = el ID ORIGINAL de la SERIE (el que mapeaste en "ID del contenido").
  {season}    = número de temporada (solo si hay endpoint de temporadas).
  {data.xxx}  = un campo extra de la serie guardado con "Otros campos" (por ejemplo {data.slug}).
  Ejemplo: /series/{id}/seasons/{season}/episodes

En PLANTILLAS y PARÁMETROS DE REPRODUCCIÓN:
  Películas: {id} = ID de la película.
  Episodios: {id} = ID del EPISODIO, {seriesId} = ID de la serie, {season} = temporada, {episode} = número de episodio.
  Siempre: {tmdb}, {imdb}, {lang} (= campo "Idioma: valor"), {data.xxx}.
  Las credenciales ({apiKey}, {token}, etc.) NO se pueden usar en plantillas: eso vuelve la fuente NO COMPATIBLE.

######################################################################
PARTE 3. SECCIÓN "IDENTIFICACIÓN Y CONEXIÓN"
######################################################################
Nombre interno: texto libre, solo para el dueño.
Nombre visible (obligatorio): lo ven los usuarios al elegir la fuente en el reproductor.
URL base de la API (obligatorio):
  - Tiene que ser https.
  - SIN parámetros (?x=...), sin usuario ni contraseña.
  - PUEDE incluir un prefijo de ruta, por ejemplo https://api.ejemplo.com/v2.
  - Todas las rutas de endpoints se AGREGAN a esta URL: base https://api.x.com/v2 + ruta /movies = https://api.x.com/v2/movies.
  - Por eso, si la documentación dice "GET https://api.x.com/v2/movies", la base es https://api.x.com/v2 y la ruta es /movies (no repetir /v2).
Método de conexión (HTTP por defecto): GET o POST. Casi siempre GET.
  OJO: con POST, los parámetros se mandan en la URL (query string), NO en un cuerpo JSON. Si la API exige un cuerpo JSON en el catálogo → PARTE 9.
Tiempo máximo por consulta (segundos): 2 a 30. Vacío = 15.
Reintentos ante errores temporales: 1 a 10. Vacío = 5. Solo para errores 5xx y de red; los 4xx fallan enseguida.
Espera inicial entre reintentos (segundos): vacío = 60; se duplica en cada reintento.
Pausa mínima entre consultas (milisegundos): vacío = 0. Ejemplo: la API permite 2 pedidos por segundo → 500.
Ventana de límite de solicitudes (segundos) + Solicitudes máximas por ventana: para límites del tipo "100 pedidos por minuto" → 60 y 100. Dejar vacío si no hay límite.
Respetar la espera que indique el servidor (Retry-After): marcar si la API devuelve 429 con Retry-After (recomendado marcar siempre).
Ante "demasiadas solicitudes" (429):
  · Esperar y seguir, sin gastar reintentos   ← recomendado
  · Contarlo como un reintento
Espera máxima aceptada (segundos): vacío = 3600.
Umbral de bajas (%) y Bajas mínimas para aplicar el umbral: protección. Vacío = 10 % y 20. Dejar vacío salvo pedido expreso.

######################################################################
PARTE 4. SECCIÓN "AUTENTICACIÓN" (para la API del CATÁLOGO)
######################################################################
Tipo de autenticación, una de:
  · Ninguna
  · API Key en un encabezado        → completar "Nombre del encabezado o parámetro de la API Key" (ej. X-Api-Key) + API Key (SECRETO)
  · API Key en un parámetro         → completar el nombre del parámetro (ej. api_key) + API Key (SECRETO)
  · Token (Authorization: Bearer)   → Token (SECRETO). Supat manda "Authorization: Bearer <token>". Usar SOLO si el token es fijo (no vence).
  · Usuario y contraseña (básica)   → HTTP Basic. Usuario y Contraseña (SECRETOS).
  · Inicio de sesión: usuario y contraseña → token   → ver abajo.
  · Solo encabezados/parámetros personalizados → cuando hacen falta varios encabezados o un formato raro (ej. "Authorization: Token abc").

Reglas para elegir:
  - "Authorization: Bearer <clave fija>" → Token (Authorization: Bearer).
  - Encabezado con otro nombre o formato ("X-Key: abc", "Authorization: Token abc", "Authorization: abc" sin Bearer)
      → API Key en un encabezado si es solo el valor (nombre = X-Key o Authorization, y la API Key debe ser el valor COMPLETO, por ejemplo "Token abc").
      → o Solo encabezados/parámetros personalizados.
  - Se pide usuario+contraseña a un endpoint y devuelve un token que vence → Inicio de sesión.
  - OAuth (redirección, client_credentials con refresh_token, scopes) → PARTE 9 (salvo que sea un POST simple usuario/contraseña → token).

Campos del INICIO DE SESIÓN (solo con ese tipo):
  Inicio de sesión: ruta → ruta relativa a la URL base, se pide SIEMPRE por POST (ej. /auth/login).
  Inicio de sesión: formato del cuerpo → JSON  o  Formulario (x-www-form-urlencoded).
  Inicio de sesión: nombre del campo de usuario → vacío = "username" (ej. email).
  Inicio de sesión: nombre del campo de contraseña → vacío = "password".
  Inicio de sesión: otros campos → nombre=valor por línea, NO secretos (ej. grant_type=password).
  Inicio de sesión: ruta del token en la respuesta (obligatorio) → ruta desde la raíz (ej. access_token o data.token).
  Inicio de sesión: ruta del vencimiento → ruta desde la raíz; puede ser segundos de duración (3600) o una fecha.
  Duración del token si la respuesta no la informa (segundos) → vacío = 3600.
  Encabezado donde va el token → vacío = Authorization.
  Prefijo del token → vacío = "Bearer " (con espacio). Para mandar el token SIN prefijo, escribir un guion: -
  Si la API responde 401, Supat renueva el token una vez y reintenta.

Encabezados personalizados (secretos) / Parámetros de autenticación adicionales (secretos):
  nombre=valor, uno por línea. Se mandan en TODAS las consultas del catálogo (y también en el endpoint de reproducción). SECRETOS.

######################################################################
PARTE 5. SECCIÓN "CATÁLOGO" Y "PAGINACIÓN"
######################################################################
Casillas: Importar películas / Importar series / Importar anime / Importar temporadas y episodios.
  - Marcar solo lo que la API tenga.
  - El TIPO de cada título lo define el ENDPOINT del que viene (todo lo de "Endpoint de películas" es película). El campo de mapeo "Tipo de contenido" NO separa tipos.
  - "Anime" es una categoría opcional; si la API no la separa, no marcarla.

Hay 6 bloques de endpoint con los MISMOS campos:
  Endpoint de películas, Endpoint de series, Endpoint de anime,
  Endpoint de temporadas (opcional), Endpoint de episodios, Endpoint de prueba de conexión (opcional).

Campos de cada bloque:
  Ruta (relativa a la URL base): empieza con "/". Ej. /movies   o  /series/{id}/episodes.
  Método HTTP: El método general / GET / POST.
  Ruta del array de resultados en la respuesta: desde la raíz hasta la lista (PARTE 1). Vacío = la respuesta es la lista.
  Parámetros: nombre=valor por línea, fijos o con variables. Ej:
      language=es
      sort=updated_at
    NO repetir acá los parámetros de paginación (page, limit...): se agregan solos.
    NO poner acá la API Key.
  Encabezados (no secretos): nombre=valor por línea. Ej: Accept-Language=es
  Campos ".page.*" de cada bloque (Paginación de este endpoint, Parámetro..., Máximo de páginas, etc.):
    SOLO hacen falta si ESE endpoint pagina distinto de la paginación general. Si todos paginan igual, dejarlos vacíos y usar la sección PAGINACIÓN.
    ¡ATENCIÓN! Un endpoint con estos campos vacíos HEREDA la paginación general. Si la general es "Número de página" y el endpoint de episodios devuelve todo junto (no pagina), hay que poner en ESE bloque "Paginación de este endpoint = Sin paginación". Si no, Supat pide page=2, recibe lo mismo y marca la importación como PARCIAL. Lo mismo para cualquier endpoint que pagine distinto (por ejemplo series con cursor y películas con página).
    "Paginación de este endpoint": Usar la paginación general (vacío) / Sin paginación / Número de página / Desplazamiento (offset) / Cursor / Enlace a la página siguiente.
    Las rutas propias de un endpoint se miden desde la raíz (NO llevan el prefijo "Ruta de la información de paginación").
    Máximo de páginas / Máximo de registros: dejar VACÍO (si se alcanza, la importación queda PARCIAL). Solo para pruebas.
    Si una página llega vacía: "Es el fin del listado" (normal).
    Si una página llega repetida: "Detener y marcar la importación como parcial" (normal).
    Si la respuesta no trae la lista esperada: "La importación falla" (normal).

ENDPOINT DE TEMPORADAS (opcional):
  - Solo si la API tiene una ruta que lista las temporadas de una serie Y los episodios se piden por NÚMERO de temporada.
  - Ruta con {id} (la serie). Ej. /series/{id}/seasons. No se pagina.
  - "Temporadas: número de temporada" (en Mapeo) = ruta del NÚMERO dentro de cada temporada (vacío = "number").
  - Después, el endpoint de episodios se llama una vez por temporada con {season} = ese número.
  - Si los episodios se piden con un ID INTERNO de temporada (no el número) → PARTE 9.
ENDPOINT DE EPISODIOS:
  - Se llama una vez por serie con {id} = ID original de la serie (y {season} si hay temporadas).
  - Ej. /series/{id}/episodes   o   /shows/{id}/season/{season}.
  - Si la API trae los episodios DENTRO de la respuesta de la serie (sin ruta propia) → PARTE 9.
ENDPOINT DE PRUEBA DE CONEXIÓN (opcional): una ruta liviana (ej. /status). Vacío = prueba con la primera página del catálogo.

SECCIÓN "PAGINACIÓN" (general, la usan todos los endpoints que no tengan la suya):
Tipo de paginación:
  · Sin paginación → la API devuelve todo en una sola respuesta.
  · Número de página → ?page=1, 2, 3...
      Necesita "Parámetro de página / offset / cursor" (ej. page).
      "Primera página": vacío = 1 (poner 0 si la API empieza en 0).
      Termina cuando: llega la última página según "Ruta del total de páginas" o "Ruta del total de resultados", o el indicador de última página es verdadero, o llega una página vacía.
  · Desplazamiento (offset) → ?offset=0, 50, 100...
      Necesita el parámetro (ej. offset o skip). Empieza en 0 y suma la cantidad de resultados recibidos.
      IMPORTANTE: si no hay "Ruta del total de resultados", termina cuando llega una página con MENOS resultados que "Resultados por página". Por eso "Resultados por página" tiene que ser EXACTAMENTE lo que la API devuelve por página (si la API tiene un máximo de 100 y se pone 200, se cortaría en la primera página).
  · Cursor → la respuesta trae un valor para pedir la siguiente página.
      Necesita el parámetro donde se manda (ej. cursor) y "Ruta del cursor o enlace siguiente" (ej. meta.next_cursor). Termina cuando ese valor viene vacío o null.
  · Enlace a la página siguiente → la respuesta trae la URL completa (o relativa) de la siguiente página.
      Necesita "Ruta del cursor o enlace siguiente" (ej. links.next o next).
      El enlace tiene que ser del MISMO servidor que la URL base. Se usa tal cual (sus parámetros reemplazan a los del endpoint).
Parámetro de página / offset / cursor: nombre del parámetro (page, offset, cursor...).
Parámetro de resultados por página: nombre (limit, per_page, page_size...). Vacío = no se manda.
Resultados por página: número. Vacío = 50. Usar el máximo que permita la API (y con offset, lo que realmente devuelve).
Primera página: vacío = 1.
Ruta de la información de paginación: PREFIJO que se agrega a las 4 rutas de abajo (ej. meta). Vacío = raíz.
  Ej.: respuesta { "meta": { "last_page": 40 } } → Ruta de la información = meta, Ruta del total de páginas = last_page.
  (Alternativa equivalente: dejar el prefijo vacío y poner meta.last_page.)
Ruta del cursor o enlace siguiente: para Cursor o Enlace.
Ruta del indicador de última página: un campo que vale true o 1 en la última página (ej. is_last, meta.last). NO es "número de la última página" (eso va en total de páginas).
Ruta del total de páginas: número total de páginas (ej. total_pages, last_page).
Ruta del total de resultados: cantidad total de títulos (ej. total, total_results).
Parámetro de "cambios desde" (incremental): solo si la API acepta pedir lo modificado desde una fecha (ej. updated_since). Se agrega a los endpoints del catálogo.
Formato de esa fecha: ISO 8601 / Fecha (AAAA-MM-DD) / Segundos Unix / Milisegundos Unix.

######################################################################
PARTE 6. SECCIÓN "MAPEO DE RESPUESTAS"
######################################################################
Todas las rutas son desde CADA ELEMENTO de la lista (PARTE 1). Supat NO transforma valores: toma el dato tal cual.

ID del contenido (OBLIGATORIO): identificador único del título en la API. Es el {id} de las otras rutas.
Tipo de contenido: opcional, solo se guarda como dato. No sirve para separar películas de series.
TMDb ID: número de The Movie Database (ej. tmdb_id). MUY recomendado: se usa para unir el mismo título entre Fuente A y B y completar datos.
IMDb ID: con formato tt1234567 (si no empieza con "tt", Supat lo descarta).
Título (OBLIGATORIO).
Título original.
Descripción.
Póster / Backdrop: URL de la imagen. Si la API da solo una ruta relativa (/img/a.jpg), completar "Prefijo de pósters con ruta relativa" (ej. https://img.ejemplo.com). El prefijo solo se agrega cuando el valor NO empieza con http. Si la API da solo un nombre de archivo o un ID de imagen que necesita armar una URL más compleja → PARTE 9.
Año: Supat toma los primeros 4 caracteres (sirve "2021" o "2021-05-03"). Si no hay año, se usa "Fecha de estreno".
Fecha de estreno.
Géneros o categorías: lista de textos. Si la API da [{ "name": "Drama" }], la ruta es genres[].name. Si da ["Drama"], la ruta es genres.
Puntaje (0 a 10): valores fuera de 0–10 se descartan (una escala de 0 a 100 NO funciona; dejarlo vacío en ese caso).
Cantidad de temporadas / Cantidad de episodios / Fecha de actualización: opcionales.
URL de reproducción (si la trae el catálogo): solo para el método "La URL viene en el catálogo".
URL de subtítulos (si la trae el catálogo): un archivo .vtt o .srt.
Otros campos: nombre=ruta por línea. Guarda datos extra para usar después como {data.nombre} en rutas y plantillas. Ej. slug=slug → {data.slug}. Solo valores simples (texto, número).
Prefijo de pósters / backdrops / imágenes de episodios con ruta relativa: ver Póster.
Temporadas: número de temporada: ver Endpoint de temporadas.
Episodios: ID (OBLIGATORIO si se importan episodios).
Episodios: número de temporada: si no se completa, se usa el {season} pedido, o 1.
Episodios: número de episodio (OBLIGATORIO si se importan episodios). Tiene que ser mayor que 0.
Episodios: título / descripción / imagen.
Episodios: duración (segundos): Supat toma el número entero del comienzo. Si la API da MINUTOS o "45 min", quedaría mal (45 segundos): en ese caso dejarlo VACÍO.
Episodios: URL de reproducción (método directo) / Episodios: URL de subtítulos.
Episodios: otros campos: igual que "Otros campos".

######################################################################
PARTE 7. SECCIÓN "REPRODUCCIÓN"
######################################################################
REGLA DE ORO: la URL final del video la abre el NAVEGADOR del usuario directamente. Tiene que funcionar sin encabezados, sin cookies y sin credenciales dentro de la URL. Si no → PARTE 9 (NO COMPATIBLE).

Método de reproducción:
  · Armar la URL (plantilla o parámetros) → la URL del video se arma con datos del título, sin consultar a la API.
  · Pedir la URL a un endpoint → el servidor de Supat consulta una ruta de la API (con la autenticación) y esa respuesta trae la URL del video. Es el método para APIs que dan enlaces firmados o temporales.
  · La URL viene en el catálogo → la URL está en cada título/episodio del catálogo ("URL de reproducción" en Mapeo).

URL base de reproducción: base para plantillas y endpoints de reproducción. Vacío = la URL base de la API.

--- Para "Armar la URL" ---
Plantilla de URL de películas: URL completa o ruta relativa a la URL base de reproducción. Ej. https://cdn.x.com/movies/{id}/master.m3u8
Plantilla de URL de episodios: Ej. https://cdn.x.com/shows/{seriesId}/{season}/{episode}.m3u8   (recordar: {id} acá es el ID del episodio).
Parámetro del identificador de película / de serie / de temporada / de episodio: si en vez de plantilla la URL lleva parámetros (?movie=..&s=..&e=..), poner el NOMBRE de cada parámetro.
Parámetros adicionales: nombre=valor por línea (sin credenciales).

--- Para "Pedir la URL a un endpoint" ---
Endpoint de reproducción de películas: ruta, ej. /movies/{id}/stream.
Endpoint de reproducción de episodios: ruta, ej. /episodes/{id}/stream. Vacío = usa el de películas.
Método HTTP del endpoint de reproducción.
Parámetro del identificador... / Parámetros adicionales: se agregan como parámetros de esa consulta.
Encabezados para pedir la URL (no secretos).
Ruta de la URL en la respuesta (OBLIGATORIO): desde la raíz de esa respuesta (ej. data.url o sources[0].file).
Ruta del formato en la respuesta (opcional): valores reconocidos: hls, m3u8, mp4, webm, application/x-mpegurl, application/vnd.apple.mpegurl, video/mp4, video/webm, embed, iframe.
Ruta del vencimiento en la respuesta (opcional): segundos de duración (3600), fecha Unix en segundos o milisegundos, o fecha ISO.
Credencial de reproducción (SECRETO) + Dónde va la credencial de reproducción:
  · No se usa
  · Encabezado (método endpoint)
  · Parámetro (método endpoint)
  · Cuerpo JSON (método endpoint)   (fuerza POST)
  La credencial solo viaja del servidor de Supat a la API, nunca al navegador.
  Solo hace falta si la API usa una credencial DISTINTA para reproducir; si es la misma API Key del catálogo, no hace falta (la autenticación del catálogo ya se manda).
Nombre del encabezado o parámetro de la credencial: obligatorio si se usa.
Subtítulos: ruta de la lista en la respuesta: ruta de una LISTA de subtítulos (ej. subtitles). Dentro de cada elemento:
  Subtítulos: campo de la URL (vacío = url), Subtítulos: campo del idioma (vacío = lang), Subtítulos: campo de la etiqueta (vacío = label).

--- Para todos los métodos ---
El servidor de video exige encabezados propios: marcar si la documentación dice que el VIDEO (no la API) necesita encabezados. → NO COMPATIBLE.
El servidor de video exige cookies: idem. → NO COMPATIBLE.
Dominios de reproducción permitidos: uno por línea, con formato EXACTO https://host (sin ruta ni barra final). Se compara el host EXACTO: si los videos salen de varios servidores (cdn1.x.com, cdn2.x.com), hay que listarlos todos. Si no se sabe, dejar VACÍO (acepta cualquiera). Obligatorio solo para reproductor externo.
Tipo de contenido:
  · Video (reproductor de Supat) → la URL es un archivo o lista HLS/MP4/WebM.
  · Reproductor externo (iframe) → la URL es una PÁGINA con su propio reproductor (embed). Requiere Dominios permitidos.
Formato de video: Detectar / HLS (.m3u8) / MP4 / WebM. "Detectar" usa la ruta de formato o la extensión de la URL. Si las URLs no tienen extensión, elegir el formato.
Subtítulos: plantilla de URL para películas / para episodios: URL de un .vtt o .srt con {lang} y las variables de la PARTE 2. Se arma una por cada idioma de la lista siguiente.
Subtítulos: idiomas: código=Nombre por línea (ej. es=Español). Se usa con las plantillas.
Subtítulos: idioma por defecto (URL del catálogo): código de idioma de las URLs mapeadas en "URL de subtítulos".
Idioma: nombre del parámetro / Idioma: valor: si la URL o el endpoint de reproducción llevan un parámetro de idioma (ej. lang=es). El valor también queda como {lang}.
Duración de los enlaces (segundos): si los enlaces vencen y la respuesta no lo dice.
Los subtítulos de otro servidor necesitan CORS habilitado; si no, se reproduce sin subtítulos.

######################################################################
PARTE 8. CÓMO SE PRUEBA (botones de la tarjeta, en orden)
######################################################################
1. Guardar configuración → dice qué falta.
2. Probar conexión.
3. Probar catálogo → cantidad de resultados, válidos, si hay más páginas y qué campos del mapeo encontró (si un campo no aparece, la ruta está mal).
4. Probar reproducción → el servidor obtiene el enlace y comprueba que responda; avisa si es NO COMPATIBLE.
5. Activar → exige lo mínimo y dice qué falta.
6. Iniciar importación. Estados: Completada / Completada con advertencias / PARCIAL (se cortó; no se borra nada) / FALLIDA (muestra la causa).
Los títulos sin TMDb ni IMDb no se unen entre fuentes (aparecen por separado).

Mínimo para activar: Nombre visible, URL base, al menos una categoría con su endpoint, Mapeo ID y Título, credenciales del tipo elegido, parámetro de paginación (si el tipo lo necesita), ruta del cursor/enlace (si es Cursor o Enlace), y si se importan episodios: Endpoint de episodios, Episodios: ID y Episodios: número de episodio.

######################################################################
PARTE 9. LO QUE SUPAT NO PUEDE HACER (avisar si la API lo necesita)
######################################################################
NECESITA CÓDIGO NUEVO (no se resuelve con ajustes):
  - Respuestas que no son JSON (XML, HTML, CSV, texto).
  - Catálogo que exige un CUERPO JSON en la consulta (búsquedas por POST con body).
  - Consultas de detalle por título (la lista trae poco y hay que pedir /movies/{id} para tener sinopsis, póster, etc.).
  - Episodios que vienen DENTRO de la respuesta de la serie (sin endpoint de episodios propio).
  - Temporadas identificadas por un ID interno (los episodios se piden con season_id, no con el número).
  - Películas y series mezcladas en el MISMO endpoint sin forma de filtrar por parámetro (si se puede filtrar, ej. ?type=movie, se usan dos bloques con ese parámetro: SÍ se puede).
  - Transformar datos: valores fijos, unir campos, convertir minutos a segundos, escala 0–100 a 0–10, códigos de tipo, armar URLs de imagen con tamaños o IDs.
  - OAuth con redirección, refresh_token propio, firma de cada solicitud (HMAC), captcha, inicio de sesión distinto para reproducir.
  - Paginación sin ninguna forma de saber el final (sin total, sin última página, sin cursor) en la que además las páginas vacías no indican el fin.
NO COMPATIBLE (por seguridad, no se va a hacer):
  - La credencial tiene que ir DENTRO de la URL del video que abre el navegador.
  - El servidor de video exige encabezados o cookies.
  - El video no permite CORS (necesario para HLS).
  - DRM (Widevine, FairPlay, PlayReady).

  URL base de la API = https://api.ejemplo.com/v2
  Tipo de autenticación = API Key en un encabezado ; Nombre = X-Api-Key ; API Key = CARGA EL DUEÑO
  Importar películas = sí ; Importar series = sí ; Importar temporadas y episodios = sí
  Endpoint de películas → Ruta = /movies ; Ruta del array de resultados = data
  Endpoint de series → Ruta = /shows ; Ruta del array de resultados = results ; Paginación de este endpoint = Cursor ;

  Endpoint de episodios → Ruta = /shows/{id}/episodes ; Ruta del array de resultados = (vacío) ; Paginación de este endpoint = Sin paginación
  Tipo de paginación = Número de página ; Parámetro = page ; Parámetro de resultados por página = per_page ; Resultados por página = 100
  Ruta de la información de paginación = meta ; Ruta del total de páginas = last_page
  ID del contenido = id ; Título = name|title ; TMDb ID = tmdb_id ; Año = release_date ; Póster = poster_path
  Prefijo de pósters con ruta relativa = NO INFORMADO (la documentación no dice el dominio de imágenes)
  Géneros o categorías = genres[].name
  Episodios: ID = id ; Episodios: número de temporada = season ; Episodios: número de episodio = episode ; Episodios: título = name
